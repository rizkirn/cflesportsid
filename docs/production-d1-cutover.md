## Configuration evidence gate

Retained approved production verification provides exact target identities, binding names/resources, active version, authentication/binding/route/settings fingerprints, and the completed schema-0011 backfill. It does not retain the actual live compatibility settings, asset routing configuration, complete route/domain configuration, workers.dev/preview settings, or genuine script settings. A fingerprint alone cannot supply the configuration values. No deployable production configuration may be inferred from `wrangler.jsonc` or UAT defaults.

Before sealing an executable deployment plan, obtain separate approval for a small GET-only configuration capture: exact account/database; active deployment before and after; active version; current settings and genuine script settings; existing domains, zone routes and workers.dev/preview settings. Compare every existing fingerprint against the retained baseline. Retain non-sensitive configuration values privately; retain authentication fingerprints and secret binding names rather than secret values. Stop on identity drift, ambiguous assets settings, split traffic or unreviewed resources. No D1 query, media request or mutation is needed just to capture these configuration values. If asset settings require another supported read endpoint, review and include it before approval; never silently add requests.

Only after that capture passes: construct the explicit production deployment configuration from those values, preserve resource bindings/routes/settings, add the six reader identity/mode variables, perform a local dry-run with that exact configuration, and issue a NEW executable deployment digest binding the configuration and artifact. The preparation seal does not authorize deployment and cannot be reused after configuration changes.
