## Architecture and decisions

- Permanent global sidebar: Overview; Competition: Tournaments, Brackets,
  Matches; Database: Teams, Players, Maps. Mobile uses a labelled native menu.
  Reason: retain orientation while preserving phone content space.
- Tournament context plus five local tabs: Overview, Participants, Roster,
  Bracket, Matches. Setup stays reachable from Overview and inspector.
  Reason: setup is configuration rather than another wizard/navigation system.
- Tournaments: searchable table, selected inspector, unlocked metadata editing,
  concise creation in a right inspector beside the tournament list.
- Brackets: tournament directory opens existing bracket workspace. Clicking a
  match opens Result + History inspector, not an embedded Details editor.
- One Edit Result form confirms initial result/progression atomically. The same
  form invokes existing correction backend for confirmed results, requiring
  reason and impact confirmation. W/O is a Result Type. Same-winner corrections
  retain downstream participants. Winner changes retain every existing guard.
  Impact lists target round/slot and whether state blocks a winner change.
- Matches: shared searchable/filterable table globally and per tournament,
  selected inspector with status, three canonical map summaries and a shortcut
  to dedicated Match Details. Authoritative score inputs and result mutation
  dispatch were removed from Details. Phase B validation/publication remains.
- Master Teams/Players/Maps: real read-only directory + inspector architecture.
  No fake CRUD. Global create/edit handlers are missing. Existing registration
  through Participants/Roster remains available.
- Palette: dark neutral operations surfaces with orange selection/action accent
  from supplied mockups. Typography retains CFL's existing condensed headings
  and readable body text. Compact rows support scanning. Flat surfaces and
  borders separate work areas; no dashboard card filler or decorative assets.

## Test lifecycle

0007 adds immutable is_test, defaulting existing tournaments to Official.
Official deletion is rejected in service and schema. Test creation stores the
flag once; inspector and workspace expose TEST. Permanent deletion requires the
exact name and explicit confirmation. It deletes owned rows in a guarded atomic
D1 batch, including correction history. It does not delete master tables.
Cross-tournament match-source references block deletion and roll back everything.
Audit updates remain forbidden; deletion exception is limited to test tournaments.
No persistent/remote migration, reset or reseed was performed. Migration SQL was
exercised only in isolated in-memory tests. Remote staging migration state was
not assumed. The existing offline visual fixture has 0005 but lacks 0006/0007;
missing correction capabilities display an explanation rather than a server crash.
