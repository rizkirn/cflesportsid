# Fix 035: isolate generated SQL fixtures in parallel tests

Test hardening only; existing R2-C application source, dependencies, runtime configuration and behavior byte-identical. Mode DURING retained; no UI changes.

## Root cause and reproduction

`tests/d1-read.test.mjs`, `tests/player-continuity.test.mjs` and `tests/assets.test.mjs` each executed the same generator and read checkout `.generated/seed-s1-s2.sql`. Each SQLite database was already in-memory/private. The generator uses async writeFile with its default truncating `w` flag. A test can complete its generator and then read the file while a different process has truncated it but has not completed its write. An empty import produces `D1 match coverage differs from the migration JSON snapshot`.

20 ordinary pre-fix runs and eight concurrent focused-suite runs did not hit the short race window. A diagnostic preload reproduced the exact interleaving without sleeps: writer opens the actual shared output with `w`, signals the parent through IPC, reader sees0 bytes and the real D1 reader rejects with the exact coverage error, then parent releases writer to complete. Shared file restored to223142 bytes. Diagnostic scripts/logs remain outside the repository under /private/tmp; none are application/test retry logic.

All three shared writers exist in approved HEAD ffefa839, before R2-C. Their introducing/modifying history includes d1-read e8e79af, continuity6bef045 and R2-A assets5db5cce. R2-C tests do not invoke this generator; adding tests merely changed scheduling when the earlier failure became visible. Exact historical first-occurrence timing is not claimed.

## Fix

`tests/helpers/seed-fixture.mjs` creates a unique mkdtemp directory per call, copies only the existing standalone generator, links existing read-only source data, runs the generator against that private path, reads SQL into a string, and removes only its own directory in finally. No second Git checkout, generator logic change or mutable shared output. All three offending consumers use it. Existing d1-parity tests already isolated their modified data/generator fixtures and remain unchanged.

`tests/seed-fixture.test.mjs` runs four generator fixture calls in separate processes concurrently, verifies identical complete output, proves the checkout seed contents and modification time are untouched, and imports the result with assertions for127 masters,5019/5010/2318 and clean FKs. One added test raises count190→191. Assertions in existing tests remain unchanged.
