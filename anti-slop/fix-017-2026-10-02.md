# Phase B compact screenshot editor

Design read: a spreadsheet replacement for CFL tournament staff entering three
match screenshots, retaining the dark admin palette and orange action accent.
ENERGY 1 / RHYTHM 2 / MOTION 1.

## Decisions

- One map-result grid aligns the three screenshots for quick comparison.
- Map tabs retain all form inputs in the DOM, reducing scrolling without losing values.
- Two roster tables share the desktop width; narrow layouts stack them and label K/D/A.
- Native radio selection puts ACE Gold beside the actual player; a 44px label target
  surrounds the smaller control. Checked state and orange IGN identify the selection.
- Sticky actions keep draft and completion reachable. The completion hint calls the
  existing `validateDetails` function; the server remains authoritative.
- Existing typography, colors and rectangular controls preserve the CFL identity.

## Evidence and limits

Browser: selecting a player with 0/0/0 enables MVP; switching Map 1 to Map 2 and
back preserves those values and selection, with one panel visible. Completed
details allow tab navigation, expose no editable K/D/A and have no save action bar.
Remote staging was only read and edited in unsaved browser fields; integration
mutations ran against the existing isolated offline server on port 4327.
No schema, migration, persistence, Phase A or public-statistics implementation changed.
No staging/production migrations or deployments, commits or staging were performed.
Real device keyboards and 200% browser zoom were not independently verified.
The final build invalidated the running dev dependency cache. The verified
remote-staging server was restarted through `npm run dev:admin` in the same
checkout; the editor, public match link and Back to Matches were rechecked.
