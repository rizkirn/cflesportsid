## Correction model

- Completed editor details open read-only. Edit Details explicitly opens the
  existing accepted values. Save Correction requires a reason and the same full
  Phase B validation; replacement of canonical rows and audit insertion share a
  guarded transaction. Edits remain in the browser until accepted.
- Series and winner corrections require a reason and an explicit confirmation
  checkbox. Same-winner changes leave downstream participants unchanged.
- A result correction removes canonical child rows in its transaction. Existing
  editor payload is retained privately as a draft requiring reconciliation and
  a reason. Full-match W/O removes detail drafts as well as all combat rows.
  Imported details remain read-only in the detail editor; result correction
  archives their canonical values in the audit before deactivating them.
- Winner/loser sources use existing match_sources. Only upcoming targets with
  zero scores, no winner/details/draft and consistent participants may change.
  Completed, W/O, live or conflicting targets block the entire transaction;
  the error identifies the target match. Historical S1/S2 and completed
  tournaments retain existing read-only protections.
- Public reads continue using canonical tables only, with unchanged S1/S2
  parity and JSON fallback. No public query reads corrections or admin drafts.
- New migration `0006_match_corrections.sql` adds append-only audit rows, UTC
  timestamps, match/tournament IDs, type, required reason and JSON old/new
  state. Update/delete triggers protect history. No actor is invented.
  Admin history shows time, type and reason in one collapsible section.
